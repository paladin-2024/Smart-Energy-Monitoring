Circuit Design & Sensor Reading

The ESP32 WROOM-32 reads voltage and current from two ADC1 pins at 2 Hz, computes power (P = V × I), and triggers local hardware alerts when consumption exceeds 150 W. Fully simulated in Wokwi — zero physical components required.

Critical Design Decision — Why ADC1 Pins?

The ESP32 has two ADC modules. ADC2 is completely disabled when the WiFi radio is active — a documented Espressif hardware limitation. Any sketch using ADC2 pins (GPIO0, 2, 4, 12–15, 25–27) for sensing will produce garbage readings the moment WiFi connects. GPIO34 and GPIO35 are ADC1-only pins that remain fully functional with WiFi running. This decision is foundational: Parts B and C both require WiFi, making the ADC1 pin choice mandatory for the entire system to function correctly.

Arduino HTTP Upload — Non-Blocking
// millis() timer — never blocks sensor loop if (millis() - lastUp >= 15000UL) { String url = BASE_URL + "?api_key=" + API_KEY + "&field1=" + String(V, 2) + "&field2=" + String(I, 2) + "&field3=" + String(P, 2) + "&field4=" + alert; http.GET(url); lastUp = millis(); }

Using millis() instead of delay(15000) means the sensor loop and OLED refresh keep running at 500ms while waiting for the upload interval. The device never freezes.

What Part B Adds Over Part A

Part A monitors locally — if no one is in the room, nobody knows about an overload. Part B fixes this. ThingSpeak stores every reading as a timestamped data point accessible from any browser, anywhere in the world. The MATLAB script runs on MathWorks' cloud infrastructure without any server setup. The React alert is entirely no-code: set field4 = 1 as the condition, enter an email address, click save. The 15-second interval is the ThingSpeak free-tier minimum — it cannot be lower without a paid plan.

Secured Pipeline & NumPy AI

MQTT over TLS replaces HTTP. An AWS Lambda function processes every reading: saves to DynamoDB, fetches live weather, runs linear regression on the last 10 readings, and publishes the prediction back to the ESP32's OLED — in under 4 seconds.

The reverse path: after Lambda computes the prediction, it publishes to energy/predictions. The ESP32 subscribes to this topic and displays the prediction on OLED line 6 — a complete bidirectional loop with <4s latency.

Lambda AI Pipeline — 6 Steps
1

Parse MQTT Event

Lambda receives the ESP32 JSON as the event object: deviceId, voltage, current, power, alert, timestamp. No parsing needed — IoT Core rule passes JSON directly.

2

Write to DynamoDB

PutItem saves the reading. Composite key: deviceId (partition) + ISO timestamp (sort) ensures chronological ordering for efficient range queries.

3

Query Last 10 Readings

ScanIndexForward=False, Limit=10 returns the 10 most recent readings. One efficient key-based read — no full table scan, cost is proportional to items read.

4

Fetch Open-Meteo Temperature

Free weather API. Kampala coordinates: 0.3163°N, 32.5822°E. No API key required. Falls back to 25°C if the request fails.

5

NumPy Linear Regression

np.polyfit(x, y, 1) fits a line through 10 readings. Extrapolate one step forward = predicted next power. Temperature correction: +0.5%/°C above 25°C. Peak hours: ×0.85.

6

Publish & Update

Update DynamoDB with predicted_power + temperature. Publish prediction JSON to energy/predictions. ESP32 shows AI: 153.2W on OLED.

NumPy Regression — How It Works

10 actual readings (dots). Dashed line = least-squares best fit by np.polyfit(x, y, 1). One step beyond the last reading = the predicted value. Temperature and peak-hour multipliers are applied after regression.

Why MQTT + TLS Instead of HTTP?

HTTP is one-way: the device asks, the cloud answers, the connection closes. MQTT is persistent and bidirectional — the device stays connected and receives predictions pushed from Lambda without ever asking for them. TLS on port 8883 with X.509 mutual certificates means both sides cryptographically prove their identity. The IoT policy grants exactly 4 permissions and nothing else: Connect, Publish to energy/monitor, Subscribe to energy/predictions, Receive from energy/predictions. A compromised device cannot read other devices' data, inject fake readings, or publish to any other topic.
